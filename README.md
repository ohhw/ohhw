## Commit Message 가이드라인

모든 저장소에 공통으로 적용합니다. 저장소마다 `COMMIT_CONVENTION.md`를 두는 경우 이 규칙을 기준으로 하고, 그 저장소에서의 타입 선택 등 적용 방법만 덧붙입니다.

- **형식:** `타입(스코프): 제목` 또는 `타입: 제목`으로 시작합니다.
- **스코프:** 변경 영역을 밝힐 때만 붙입니다.
- **본문:** 제목 아래 한 줄을 비우고 변경 내용을 `-` 목록으로 적습니다.
- **제목:** 50자 이내로 쓰고 끝에 마침표를 붙이지 않습니다.
- **원칙:** 한국어를 기본으로 쓰고, 영문 제목은 명령조로 씁니다. 커밋 하나에는 목적 하나만 담습니다.
- **관련 이슈:** 실제 관련 이슈가 있을 때만 본문 아래 한 줄을 비우고 `Refs: #번호`를 적습니다. 없는 이슈를 만들거나 번호를 추정하지 않습니다.
- **이력:** 완료된 과거 커밋은 다시 쓰지 않습니다. 원격 이력을 확인한 뒤 그 위에 새 커밋을 만듭니다.
- **PR:** 제목은 커밋과 같은 형식으로 쓰고, 본문에는 변경 이유·내용·검증 결과를 적습니다. 실행하지 않은 검사는 통과로 표시하지 않습니다. 병합으로 생기는 커밋 메시지도 이 규칙을 따릅니다.

### 타입

| 타입 | 사용 시점 |
| --- | --- |
| `feat` | 기능 추가·개선 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `style` | 동작에 영향 없는 표현·포맷 변경 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `chore` | 설정·빌드·의존성 관리 |

### 예시

#### feat

```text
feat(ui): 다크 모드 추가

- 화면 테마 전환 버튼 추가
- 선택한 테마 저장
```

#### fix

```text
fix(search): 검색 결과 누락 수정

- 빈 검색어를 처리하는 조건 수정
- 결과가 없을 때 안내 메시지 표시
```

#### docs

```text
docs(readme): 설치 방법 보완

- 설치 전 요구 사항 명시
- 실행 명령 예시 추가
```

#### style

```text
style(button): 버튼 간격 정리

- 버튼 사이 여백 통일
- 동작 변경 없이 화면 표현 조정
```

#### refactor

```text
refactor(api): 응답 처리 함수 분리

- 중복된 응답 처리 로직 통합
- 기존 동작 유지
```

#### chore

```text
chore(deps): 의존성 버전 갱신

- 패키지 버전 업데이트
- 잠금 파일 동기화
```
