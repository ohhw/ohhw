## Commit Message 가이드라인

변경 목적이 한눈에 보이도록 제목을 먼저 적습니다.

### 형식

```text
타입(스코프): 제목
```

스코프는 변경 영역을 밝힐 때만 붙입니다. 설명이 더 필요하면 제목 아래에 빈 줄을 두고 본문을 적습니다. 관련 이슈나 호환성 변경 사항은 본문 아래에 빈 줄을 두고 바닥글에 기록합니다. 빈 줄은 제목·본문·바닥글을 구분하기 위한 커밋 메시지 형식입니다.

### 타입

| 타입 | 용도 |
| --- | --- |
| `feat` | 기능 추가·개선 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `style` | 동작에 영향이 없는 포맷팅·표현 변경 |
| `refactor` | 기능 변경 없이 코드 구조 개선 |
| `chore` | 설정·빌드·저장소 관리 등 기타 작업 |

### 작성 원칙

제목은 50자 이내로 쓰고 끝에 마침표를 붙이지 않습니다. 영문 제목은 명령조를 사용합니다. 한 커밋은 하나의 목적에 집중합니다. 세부 작업이 여러 개라면 본문에 목록으로 적습니다.

### 예시

```text
docs(readme): 설치 방법 정리
```
