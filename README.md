## Commit Message 가이드라인

커밋 메시지는 변경 목적이 한눈에 보이도록 다음 형식으로 작성합니다.

```text
타입(스코프): 제목

- 변경 내용과 이유
- 함께 처리한 세부 작업

Refs: #이슈번호
```

스코프는 해당 영역을 명확히 밝힐 때 사용합니다. 본문은 변경 이유와 내용을 적고, 바닥글에는 관련 이슈나 호환성 변경 사항을 기록합니다.

| 타입 | 용도 |
| --- | --- |
| `feat` | 기능 추가·개선 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `style` | 동작에 영향이 없는 포맷팅·표현 변경 |
| `refactor` | 기능 변경 없이 코드 구조 개선 |
| `chore` | 설정·빌드·저장소 관리 등 기타 작업 |

제목은 50자 이내로 쓰고 끝에 마침표를 붙이지 않습니다. 영문 제목은 명령조를 사용합니다. 한 커밋은 하나의 목적에 집중하고, 불가피하게 여러 세부 작업을 함께 담았다면 본문에 목록으로 구분합니다.

변경 전:

```text
20260929a
1. 축하 메시지를 Google Forms로 전환
2. 안내 문구 개선
```

변경 후:

```text
feat(guestbook): 축하 메시지를 Google Forms로 전환

- 기존 방명록 연결을 설문 링크로 교체
- 안내 문구 개선

Refs: #12
```
